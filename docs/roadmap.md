## v0.7.0 — 통계·타임라인 + 원격 동기화 UX

### 1. 커밋 상세: 변경 라인 수 집계 `[draft]`

- **R-01** 커밋 상세 뷰 헤더에 해당 커밋의 **총 추가/삭제 라인 수**를 `+N / −M` 형태로 표시한다.
- **R-02** 집계에서 **공백만 있는 줄과 주석 줄은 제외**한다. 즉 `git diff --numstat` 값을 그대로 쓰지 않고, 실질 코드 라인만 센 별도 수치를 낸다.
- **R-03** 원시 수치(numstat 기준)와 실질 수치를 함께 보여줄지, 실질 수치만 보여줄지는 미확정. 툴팁에 원시 수치를 넣는 방향이 유력.

**미확정 / 조사 필요**

- 주석 판별은 언어별 문법 문제다. 파일 확장자 → 주석 토큰 테이블(`//`, `#`, `--`, `/* */`, `<!-- -->` …)로 근사할지, 아니면 확장자 화이트리스트에서만 집계하고 나머지는 원시 수치로 표시할지 결정 필요.
- 문자열 리터럴 안의 `//` 같은 오탐을 어디까지 감수할지 (완전 파싱은 비용 대비 효익이 낮음).
- 큰 커밋에서의 성능 — diff 본문을 실제로 읽어야 하므로 상세 뷰 진입 시 지연 가능. 비동기 계산 후 나중에 채우는 방식 검토.

### 2. 작업자별 커밋 수 조회 `[draft]`

- **R-04** 특정 작성자의 커밋 수를 조회한다. 진입점 후보: 커밋 행의 아바타/작성자 우클릭 → "이 작성자의 커밋 보기", 또는 툴바의 통계 버튼.
- **R-05** 결과에는 최소한 커밋 수를 표시하고, R-01의 라인 수 집계를 재사용해 추가/삭제 라인 합계도 함께 낼 수 있다.
- **R-06** 집계 범위(현재 로드된 커밋만 / 전체 히스토리 / 브랜치·기간 한정)를 명시적으로 선택할 수 있어야 한다. 로드된 범위만 세면 증분 로딩 때문에 숫자가 계속 변해 오해를 준다.

**미확정**

- 동일인이 여러 이메일을 쓰는 경우(회사/개인 계정) 병합 여부. `.mailmap` 인식이 정석.

### 3. 커밋 타임라인 뷰 `[draft]`

- **R-07** 그래프와 별개의 **타임라인 뷰**를 제공한다. 커밋을 시간 축에 집계해 활동량을 보여준다.
- **R-08** 축 단위는 **일 / 월 / 연** 전환 가능.
- **R-09** **작업자별** 구분 표시 (스택 막대 또는 작업자별 행). 작업자 필터로 특정 인원만 볼 수 있다.
- **R-10** 타임라인의 한 구간을 클릭하면 그래프 뷰가 해당 기간의 커밋으로 스크롤/필터되는 연동이 목표.

**미확정**

- 뷰 위치: 별도 에디터 탭 / 그래프 뷰 내 패널 전환 / 하단 분할 패널 중 택1.
- 렌더링 방식: 그래프와 마찬가지로 커스텀 SVG로 직접 그린다 (차트 라이브러리 의존 추가는 지양).

### 4. 스태시 창 개선 `[planned]`

현재 스태시는 그래프 노드/라벨과 우클릭 메뉴로만 다룬다(`docs/spec/20-actions.md` §6). GitLens의 STASHES 패널과 비슷한 **목록형 UI**를 추가한다.

- **R-11** 스태시 전용 섹션에 전체 스태시를 목록으로 보여준다. 섹션 헤더에 **총 개수**를 표시한다 (예: `STASHES (32)`).
- **R-12** 각 행 구성: 펼침 화살표 + 스태시 메시지 + **생성 당시 브랜치명 뱃지** + **상대 시각**(`6 days ago`, `last week`, `3 weeks ago`, `last month`).
- **R-13** 행을 펼치면 그 스태시에 포함된 **변경 파일 목록**이 나온다.
- **R-14** 행 hover 시 우측에 인라인 액션 아이콘을 노출한다: **Apply / Pop / 비교(diff) / 이름 변경 / 삭제(Drop)**. 기존 우클릭 메뉴 항목과 동작은 동일하고 접근 경로만 늘리는 것이다.
- **R-15** 섹션 헤더에도 액션을 둔다: 새 스태시 생성(uncommitted changes 스태시), 전체 새로고침.
- **R-16** 파괴적 액션(Drop, Pop)은 기존 규칙대로 확인 다이얼로그를 유지한다.

**미확정**

- 배치: 그래프 뷰 내 사이드 패널 / VS Code 사이드바 트리 뷰 중 택1. 사이드바 트리 뷰가 이미지의 형태에 가깝지만 웹뷰 UI 자산을 재사용하지 못한다.
- "이름 변경"은 git이 직접 지원하지 않는다(스태시 메시지 수정은 drop+재생성 또는 ref 재작성). 위험도 대비 가치 재검토 필요 — 최악의 경우 제외한다.

### 5. Fetch 후 origin 브랜치 체크아웃 시 자동 pull `[planned]`

- **R-17** 원격 브랜치를 체크아웃할 때, **동일한 이름의 로컬 브랜치가 이미 존재하면** 새 추적 브랜치를 만들려다 실패하는 대신 해당 로컬 브랜치를 체크아웃하고 **바로 pull**한다.
- **R-18** 이때 로컬 브랜치가 원격보다 앞서 있거나 갈라진 경우(diverged)에는 자동 pull 하지 않고, 무엇이 다른지 알린 뒤 사용자에게 선택을 넘긴다.
- **R-19** 동작이 "체크아웃만" 이 아니라는 점이 사용자에게 보여야 한다 (확인 다이얼로그 문구 또는 실행 후 결과 표시).

### 6. 툴바에 pull 버튼 추가 `[planned]`

- **R-21** 업스트림이 없는 브랜치에서는 비활성화하고, 이유를 툴팁으로 알린다.
- **R-22** 실패(충돌 등) 시 git stderr를 그대로 보여주는 기존 에러 표시 규칙을 따른다.

### 7. 브랜치 뱃지 우클릭 → 체크아웃 없이 pull `[draft]`

- **R-23** 브랜치 뱃지 우클릭 메뉴에 **해당 브랜치만 pull** 항목을 추가한다. 현재 브랜치를 바꾸지 않고, 워킹 트리 변경사항에도 손대지 않는다.
- **R-24** 구현은 fast-forward만 허용하는 방식(`git fetch <remote> <branch>:<branch>` 계열)을 기본으로 한다. fast-forward가 불가능하면 실행하지 않고 이유를 알린다 — 체크아웃 없이 머지 커밋을 만들지 않는다.
- **R-25** 현재 체크아웃된 브랜치에 대해서는 이 항목 대신 일반 pull(R-20)로 동작한다.

### 8. git 관련 아이콘 개선 `[draft]`

- **R-27** 라이트/다크 테마 모두에서 대비를 확인한다. VS Code Codicon과의 일관성을 기본 방향으로 한다.

### 9. 브랜치 필터: 원격에만 있는 브랜치 감추기 `[planned]`

- **R-28** 브랜치 필터 드롭다운 **상단**에 "원격에만 존재하는 브랜치 숨기기" 토글을 추가한다.
- **R-29** 켜면 **대응하는 로컬 브랜치가 없는 원격 브랜치**를 그래프·뱃지·필터 목록에서 제외한다. 로컬 브랜치가 있는 원격 브랜치(내가 작업 중인 것)는 그대로 보인다.
- **R-30** 기존 **Show Remote Branches** 토글(`docs/spec/30-search-filter.md` §30.2)과는 다른 축이다. 그쪽은 원격 전부를 끄고, 이쪽은 "남의 브랜치만" 끈다. 두 토글의 관계를 UI에서 헷갈리지 않게 배치한다.
- **R-31** 세션 상태로 저장한다 (VS Code 설정 아님) — 기존 Show Remote Branches와 동일한 취급.

**의도**: fetch 후 다른 사람의 원격 브랜치가 한꺼번에 나타나 그래프가 읽기 어려워지는 상황을 막는다.

- **R-34** 숨긴 브랜치가 있으면 브랜치 드롭다운에 그 사실과 개수를 표시하고, 거기서 **개별 해제 / 전체 해제**를 할 수 있어야 한다. 숨긴 사실을 되돌릴 경로가 없으면 안 된다.
- **R-35** 세션 상태로 저장한다 (R-31과 동일한 취급).

### 11. 다이얼로그 열릴 때 입력 필드 자동 포커스 `[planned]`

- **R-36** 모달/다이얼로그가 열리면 **첫 번째 입력 필드(`input` / `textarea`)에 즉시 포커스**를 준다. 마우스로 필드를 다시 클릭하지 않고 바로 타이핑할 수 있어야 한다.
- **R-37** 대상 다이얼로그: 브랜치 생성(이름 입력), 스태시 생성(메시지 입력), 태그 생성, `Reset HEAD~N`(숫자 입력), 브랜치 필터 glob 입력 등 입력 필드를 가진 모든 다이얼로그.
- **R-38** 기존 값이 채워진 필드는 **전체 선택 상태**로 포커스해 바로 덮어쓸 수 있게 한다. 커서만 놓아야 하는 경우(값 뒤에 이어 쓰는 필드)는 예외로 둔다.
- **R-39** 입력 필드가 없는 확인 전용 다이얼로그에서는 **확인 버튼에 자동 포커스를 주지 않는다**. `--hard` reset, Drop Stash 등 파괴적 액션에서 Enter 한 번에 실행되는 사고를 막는다 — 이 경우 포커스는 다이얼로그 컨테이너에 둔다.
- **R-40** 포커스 트랩: 다이얼로그가 열린 동안 Tab 순환은 다이얼로그 내부에 갇히고, 닫으면 **직전에 포커스를 갖고 있던 요소로 복귀**한다.
- **R-41** Enter로 확정 / `Esc`로 취소하는 기존 키 동작(`docs/spec/20-actions.md`)과 함께 검증한다. `textarea`에서는 Enter가 줄바꿈이어야 하므로 확정 키를 별도로 정한다.

### 13. 충돌 상태 표시 + 중단 버튼 `[planned]`

머지·리베이스·체리픽·리버트가 충돌로 멈춘 상태를 그래프에서 바로 알아보고, 그 자리에서 중단할 수 있게 한다. 지금은 그래프 맨 윗줄이 `Uncommitted changes (N)`만 보여주므로, 소스 제어 뷰를 봐야 충돌로 멈춘 상태임을 알 수 있다.

- **R-45** 그래프 **맨 윗줄 `Uncommitted changes` 행**에 진행 중인 작업 종류를 뱃지로 표시한다: `merging` / `rebasing` / `cherry-picking` / `reverting`. 충돌 파일이 있으면 그 개수도 함께 보여준다.
- **R-46** 충돌 상태의 행은 색으로 구분해 평소의 uncommitted changes 행과 한눈에 구별되게 한다.
- **R-47** 같은 행에 **중단(Abort) 버튼**을 둔다. 진행 중인 작업 종류에 맞는 중단을 실행한다 (머지 / 리베이스 / 체리픽 / 리버트).
- **R-48** 중단은 워킹 트리를 되돌리는 파괴적 액션이므로 기존 규칙대로 **확인 다이얼로그**를 띄운다. 다이얼로그에는 무엇이 중단되고 어느 상태로 돌아가는지 적는다.
- **R-49** 리베이스 중에는 중단 외에 **계속(Continue) / 건너뛰기(Skip)** 도 같은 자리에서 노출할지 검토한다. 계속은 충돌이 모두 해결된 뒤에만 활성화한다.
- **R-50** 충돌 파일의 **해결 UI는 만들지 않는다**. 충돌 파일 클릭은 VS Code 내장 merge editor로 넘긴다 (`Plan.md` 비목표 유지).

**미확정**

- 진행 중 작업 판정은 `.git`의 `MERGE_HEAD` / `rebase-merge`·`rebase-apply` / `CHERRY_PICK_HEAD` / `REVERT_HEAD` 존재 여부로 하고, 충돌 파일은 `git status`의 `U` 항목에서 얻는다. 기존 워처 갱신 경로에 얹을 수 있는지 확인 필요.
- 머지 대상(`MERGE_HEAD`)·리베이스 진행 지점(`REBASE_HEAD`) 커밋을 그래프에서 함께 강조할지 — 유용하지만 충돌 표시와 별개 축이므로 분리 가능.

### 14. 워크트리·서브모듈에서 커밋 메시지 기본값 채우기 `[planned]`

0.6.3에서 squash 머지 뒤 커밋 메시지 기본값을 `MERGE_MSG`에 옮겨 적도록 고쳤다(`seedSquashMergeMessage`). 경로는 `rev-parse --git-path`로 얻으므로 워크트리·서브모듈에서도 **올바른 파일에 정확히 쓴다**. 그런데 그 파일을 읽어 입력칸에 넣는 쪽은 VS Code 내장 git이고, 그쪽이 워크트리에서 읽지 못한다 — `extensions/git/src/git.ts`의 `getMergeMessage()`가 `path.join(repositoryRoot, '.git', 'MERGE_MSG')`로 경로를 조립하는데 워크트리·서브모듈의 `.git`은 디렉토리가 아니라 gitdir 경로가 적힌 파일이라 `ENOTDIR`로 실패하고, `catch`가 이를 "메시지 없음"으로 삼킨다. 결과적으로 GitScope가 제대로 써도 입력칸은 빈 채로 남는다.

- **R-51** 워크트리·서브모듈에서는 `MERGE_MSG` 기록에 더해 **내장 git 익스텐션 API로 입력칸에 직접 넣는다** (`vscode.git` → `getAPI(1)` → `getRepository(root).inputBox.value`). 내장 git이 `MERGE_MSG`를 못 읽는 환경에서도 터미널에서 커밋할 때와 같은 기본 메시지가 뜬다.
- **R-52** 일반 저장소에서는 직접 주입하지 않는다. 내장 git이 `MERGE_MSG`를 정상적으로 읽으므로 중복 경로가 되고 사용자 입력 보호 규칙과 어긋난다. `.git`이 파일인지 여부(= 워크트리·서브모듈)로 분기한다.
- **R-53** 이미 입력칸에 사용자가 쓴 내용이 있으면 덮어쓰지 않는다. 0.6.3의 "주석이 아닌 줄이 있으면 유지" 규칙을 입력칸에도 동일하게 적용한다.
- **R-54** 내장 git이 없거나 비활성(`git.enabled: false`)이거나 API 버전이 맞지 않거나 `getRepository()`가 `null`이면 조용히 넘어간다. 머지 결과 자체에는 영향이 없어야 한다 (0.6.3과 동일한 실패 정책).
- **R-55** squash 전용이 아니라 **머지 계열 액션 공통**으로 적용한다. 일반 머지(`--no-ff` 포함)·체리픽·리버트도 같은 경로로 기본 메시지가 사라진다.
- **R-56** 근본 원인은 업스트림에 있으므로 수정 제안을 병행한다. `getMergeMessage()`·`getSquashMessage()`가 이미 익스텐션 내부에 있는 `dotGit.path`를 쓰도록 바꾸는 소규모 변경이며, 반영되면 R-51 우회를 제거할 수 있다.

**미확정**

- 주입 시점: 머지 명령 직후 한 번으로 충분한지, 이후 내장 git이 `commitTemplate`을 빈 값으로 갱신하며 지워버리는지 확인 필요. 워크벤치는 입력칸에 값이 있고 그것이 직전 템플릿과 다르면 덮어쓰지 않으므로(`scmInput.ts`) 한 번으로 충분할 가능성이 높다.
- `git.showCommitInput: false`로 입력칸을 숨긴 사용자에게는 주입 자체를 건너뛸지.
- 서브모듈을 GitScope가 어떤 단위로 저장소로 취급하는지(`listRepos`)에 따라 대상 판정 기준이 달라질 수 있다.
- 같은 경로 조립 버그로 워크트리에서는 내장 git의 `MERGE_HEAD`·`rebase-merge`·`CHERRY_PICK_HEAD` 감지도 실패한다. 13번(R-45)의 상태 판정을 GitScope가 자체적으로 하면 이 영향은 받지 않지만, 내장 git의 context key(`gitMergeInProgress`)에 기대는 UI는 워크트리에서 동작하지 않는다는 점을 전제로 둔다.

## v0.8.0 — 에디터 인라인 blame

### 12. 라인별 최근 수정자 표시 `[research]`

- **R-42** 코드 에디터에서 커서가 있는 줄(또는 모든 줄)에 **해당 라인을 마지막으로 수정한 사람 / 시각 / 커밋 요약**을 인라인으로 표시한다. GitLens의 라인 blame과 유사한 기능.
- **R-43** 표시 항목을 클릭하면 그래프 뷰에서 해당 커밋으로 이동한다 — 이 연동이 GitScope가 별도 blame 확장과 차별화되는 지점이다.
- **R-44** 설정으로 켜고 끌 수 있어야 하며, **기본값은 꺼짐**을 검토한다 (GitLens 등과 동시 사용 시 화면이 중복된다).

**조사 필요**

- 성능: `git blame`은 파일 단위로 비싸다. 파일 열 때 1회 실행 + 편집 중 무효화 정책, 큰 파일 임계치 설정 필요.
- 표시 수단: `DecorationOptions`의 `after` 텍스트(GitLens 방식) / hover / status bar 중 어디까지 할지.
- 이 기능은 웹뷰가 아닌 **에디터 확장 영역**이라 지금까지의 FSD 구조 바깥이다. 배치 규칙을 `fsd-architecture` 기준으로 먼저 정리해야 한다.
