# Cleanroom Guard

GitScope는 Git Graph(mhutchie/vscode-git-graph)의 클린룸 재구현이다. 원본은 파생물 배포를 금지하는 라이선스라서, **우리 코드가 원본 코드에서 유래하지 않았음**이 배포 합법성의 근거다. 아래 규칙은 예외 없이 적용한다.

## 금지 (읽지도, 열지도 않는다)

- `../vscode-git-graph/src/**`, `web/**` 등 원본의 모든 구현 소스 파일
- 원본 소스를 인용/요약한 블로그·스택오버플로 답변의 코드 블록 (출처가 원본 코드면 동일하게 오염)
- 원본을 포팅·변환·리팩토링하는 방식의 "재작성"
- (neo) Git Graph 등 원본 파생 포크의 소스 — 라이선스 근거가 불안정하므로 동일 취급

작업 중 실수로 원본 소스가 컨텍스트에 들어왔다면: 해당 내용을 코드에 반영하지 말고, 사용자에게 알린 뒤 그 파일과 무관한 방식으로 다시 설계한다.

## 허용 (마음껏 참조)

| 참조 대상 | 용도 |
|---|---|
| [Git Graph 공식 위키](https://github.com/mhutchie/vscode-git-graph/wiki) | 기능·설정의 사실 정보 추출 (문장 복붙은 금지, 사실만) |
| 원본 익스텐션을 설치해서 사용자로서 관찰 | 블랙박스 동작 분석 — UX, 메뉴 구성, 엣지케이스 |
| 원본 `package.json`의 `contributes` 섹션 | 커맨드/설정 인벤토리 (기능적 사실 데이터) |
| git 공식 문서 (`git help <cmd>`, git-scm.com) | 명령어 옵션·출력 포맷 |
| VS Code Extension API 문서, 공식 샘플 | Webview, SCM, TreeView 등 API 사용법 |
| GitLens, GitLG 등 **독립 구현** 오픈소스의 아이디어 | 단, 코드 복사 시 해당 프로젝트 라이선스 준수 |

## 막혔을 때 절차

"원본은 이걸 어떻게 했지?"라는 생각이 들면:

1. `docs/spec/`의 명세에 동작이 기술되어 있는지 확인
2. 없으면 원본 익스텐션을 **실행해서** 동작을 관찰하고 명세에 추가 (spec-extract)
3. 구현 방법 자체가 문제면 git 공식 문서와 VS Code API 문서에서 해법을 찾는다
4. 그래도 안 되면 원본과 다른 방식을 새로 설계한다 — 원본 소스를 여는 것은 선택지가 아니다
